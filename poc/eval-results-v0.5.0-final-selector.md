# v0.5.0 — Final Selector 평가 결과 (2026-10-26)

baseline(v0.4.3) 파이프라인의 2.5단계와 3단계 사이에 **Final Selector**를 추가하고,
같은 100개 평가셋으로 baseline과 비교한 기록.

## 실험 개요

- **질문**: Final Selector를 추가했을 때, 정답 아이템은 최대한 보존하면서 주변적이거나
  중복된 후보를 제거해 Precision과 실제 수집 품질을 높일 수 있는가?
- **Final Selector의 역할**: 2단계 KEEP(ACTIVITY 제외) 후보와 2.5단계 COLLECTIBLE 후보에
  `id`를 붙인다. 이 후보 전체를 원문과 함께 한 번에 보여주고, 그 순간을 대표하는
  후보의 `selected_ids`만 고르게 한다. 고른 id로 기존 candidate 객체를 그대로 걸러서
  3단계에 넘긴다. 새 후보 생성이나 name/category/evidence 수정은 하지 않는다.
- **스키마 검증**: JSON Schema `enum`으로 입력 id만 고르도록 유도한다. Zod로 입력에 없는
  id와 중복 id를 다시 막고, 걸리면 invalid로 처리해서 재시도한다.
- **고정 조건**: Stage 1/2/2.5/3 프롬프트와 로직, 100개 평가셋, expected, 모델
  (`gemma3:4b-it-q8_0`), inference 설정(temperature 0)은 모두 baseline과 같다.
- **Few-shot 예시**: 처음 실행할 때는 예시 4개가 평가셋 문장과 거의 같았다(창문/밤바람,
  첫눈/포장마차, 김치전/막걸리, 여행 중 서점). 그래서 평가셋 500개 전체에 한 번도
  나오지 않는 단어로만 다시 만들었다. 이 문서의 v0.5.0 수치는 **바꾼 예시로 실행한
  결과**다.

  | 예시 | 역할 | 후보 | 선택 |
  | --- | --- | --- | --- |
  | 1 | 중복과 배경 제거 | 베란다 / 유성우 / 유성 | 유성우 |
  | 2 | 여러 개 선택, 배경 제거 | 장터 / 꽈배기 / 손난로 | 꽈배기, 손난로 |
  | 3 | 의미 약한 조각 제거 | 수정과 / 인절미 / 손수 / 한 조각 | 수정과, 인절미 |
  | 4 | PLACE가 핵심이면 선택 | 출장 / 문방구 | 문방구 |

- **로그**
  - baseline: `poc/eval-run-100-full-v0.4.3.log`
  - v0.5.0: `poc/eval-run-100-final-selector-clean-examples.log`
  - 예시가 평가셋과 겹쳤던 첫 실행(참고용): `poc/eval-run-100-final-selector.log`

## 핵심 지표 요약

| 지표 | baseline (v0.4.3) | v0.5.0 (Final Selector) | 변화 |
| --- | --- | --- | --- |
| **Precision** | 48.4% | **72.9%** | **+24.5%p** |
| **Recall** | 80.2% | **72.9%** | **−7.3%p** |
| **F1** | 60.4% | **72.9%** | **+12.5%p** |
| TP / FP / FN | 77 / 82 / 19 | 70 / 26 / 26 | FP −56, FN +7 |
| 아이템 매치율 | 77/96 (80.2%) | 70/96 (72.9%) | −7.3%p |
| Edge-case Pass Rate | 16/18 (88.9%) | 17/18 (94.4%) | +1건 |
| 케이스당 평균 최종 아이템 수 | 1.59개 | 0.96개 | −0.63개 |
| 에러 / 스키마 재시도 | 0 / 0 | 0 / 0 | - |

결론: Precision과 F1은 크게 올랐다. Recall은 7.3%p 떨어졌다. 같은 실행의 Selector
입력과 비교하면 TP가 78 → 70으로 8개 줄었고, 8개 모두 Selector가 정답을 지운 것이다
(아래 "Selector가 제거한 정답" 참고).

### Selector가 제거한 정답 8건

| 메모 | Selector가 선택 | 지운 정답 |
| --- | --- | --- |
| 비 오는 날 창가에 앉아서 따뜻한 라떼 마시면서 좋아하는 책 읽었어. | 라떼 | 책(사물) |
| 첫눈 오는 날 포장마차에서 어묵 국물 마시니까 몸이 사르르 녹았다. | 어묵 | 첫눈(자연) |
| 여름밤 평상에 앉아 먹은 수박 한 조각이 그렇게 시원할 수 없었다. | 수박 | 평상(사물) |
| 오래된 골목 사이 카페에서 낡은 나무 테이블에 앉아 커피를 마셨다. | 나무 테이블, 커피 | 카페(장소) |
| 바다가 보이는 벤치에 앉아 한참을 아무 말 없이 있었다. | 바다 | 벤치(사물) |
| 캠핑장에서 텐트 밖으로 보이는 별이 도시에서 본 것과 완전히 달랐다. | 별 | 텐트(사물) |
| 퇴근하고 강아지랑 산책하는데 하늘에 별이 엄청 많았다. | 별 | 강아지(동물) |
| 새벽까지 게임을 하다 마지막 판을 이겼을 때 소리를 질렀다. | 판 | 게임(활동) |

**실패 패턴**

1. **정답이 두 개면 하나만 남긴다.** 8건 중 7건이 정답 두 개 중 하나만 골랐다.
   "같은 의미면 대표 하나만"이라는 규칙을 "대표 하나만 고르기"로 넓게 받아들인 것으로
   보인다.
2. **앉거나 머무르는 대상을 배경으로 본다.** 평상, 벤치, 텐트, 카페, 책처럼 그 위나
   안에 있는 대상이 계속 지워진다. PLACE/OBJECT 선택 반례(예 2, 예 4)를 넣었는데도
   거의 그대로였다.
3. **구체성 판단을 틀린다.** 게임 케이스에서 `게임` 대신 의미가 약한 조각인 `판`을
   골랐다.

### Selector 이후 남은 FP 26건

국밥집(PLACE), 국물(OBJECT), 나무 테이블(OBJECT), 바다(PLACE), 열람실(PLACE),
호수(PLACE), 밤바람(OBJECT), 눈길(NATURE), 가을(NATURE), 바닷가(PLACE), 흙(NATURE),
하늘(NATURE), 창문(OBJECT), 벚꽃잎(OBJECT), 산 정상(PLACE), 물(OBJECT),
턴테이블(OBJECT), 자전거(OBJECT), 한강(PLACE), 보드게임(OBJECT), 빵(FOOD),
그림(OBJECT), 완성작(OBJECT), 수영장(PLACE), 판(OBJECT), 피아노(OBJECT)

- `밤바람(OBJECT)`, `벚꽃잎(OBJECT)`, `자전거(OBJECT)`처럼 아이템 자체는 맞지만
  2단계에서 카테고리가 틀린 경우가 섞여 있다. 이런 경우는 FP와 FN에 동시에 잡힌다.
  Selector가 아니라 2단계 문제다.
- 반대로 Selector가 지운 non-expected 후보에는 노을, 밤하늘, 달, 바다, 캠핑, 등산,
  산책처럼 수집 아이템으로 괜찮아 보이는 것도 있다. expected가 정답을 전부 담고 있지는
  않아서, Non-expected Removal Rate만으로 품질을 판단하면 안 된다.

## 판단 포인트

- 목표였던 "Precision ↑, F1 ↑"는 달성했다(+24.5%p, +12.5%p).
- "Recall 유지 또는 소폭 하락"에 대해서는, −7.3%p가 소폭인지 판단이 필요하다.
  Selector가 정답을 보존하는 비율은 89.7%다.
- Recall 하락은 대부분 "정답이 두 개면 하나만 남기기" 패턴에서 나온다. 다음에
  프롬프트를 고친다면 고칠 곳은 이 하나로 좁혀진다.
